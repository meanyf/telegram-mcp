# Telegram MCP

Сбор сообщений выбранных Telegram-чатов, анализ в ChatGPT и доставка сводки
в личный диалог с Telegram-ботом.

```text
Telegram → сборщик Python → SQLite → MCP → ChatGPT → Telegram-бот
```

Сборщик работает через личный аккаунт Telegram. MCP передаёт ChatGPT ещё
не выданные сообщения за последние 24 часа. Правила анализа задаются в
`prompts/mcp_instructions.md`, расписание — в ChatGPT.

## Требования

- Linux x86_64 или arm64.
- Python 3.10+ с модулем `venv`.
- Telegram-аккаунт и ключи приложения `api_id` и `api_hash`.
- Аккаунт ngrok и authtoken для публичного подключения MCP.
- Telegram-бот для получения сводок.
- ChatGPT с возможностью подключения собственного MCP-сервера.

Для работы нужны включённый компьютер без сна и доступ к интернету.
Все команды выполняются из корня проекта.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

## Настройка Telegram

Получите `api_id` и `api_hash` в разделе **API development tools** на
[my.telegram.org](https://my.telegram.org). Порядок регистрации приложения
описан в [документации Telegram](https://core.telegram.org/api/obtaining_api_id).

```bash
.venv/bin/python -m telegram_mcp.telegram_collector setup
```

Введите ключи в терминале. Для входа откройте Telegram на телефоне:
**Настройки → Устройства → Подключить устройство** и отсканируйте QR.
Если включена двухэтапная проверка, введите её пароль в терминале.

QR также доступен в `.local/telegram/login-qr.svg`: его можно открыть в браузере.
При истечении срока QR обновляется, максимум три попытки. Файл удаляется
после завершения или остановки входа.

Выберите номера чатов через запятую. При повторном `setup` выберите режим:
**добавить чаты** (по умолчанию) или **заменить список целиком**.
В режиме добавления укажите только новые чаты; прежние сохранятся, повторный
выбор одного чата не создаёт дублей. Уже выбранные чаты отмечены в списке.
В режиме замены укажите все чаты, которые должны остаться.
Перед настройкой остановите сборщик, после сохранения запустите его снова.
Сессия сохраняется, поэтому повторный вход требуется при её отсутствии или отзыве.

## Настройка бота для сводок

Создайте бота через [@BotFather](https://t.me/BotFather) и получите его токен:
`/mybots` → выбрать бота → **API Token**. Откройте созданного бота с аккаунта,
на который хотите получать сводки, и нажмите **Start**.

```bash
.venv/bin/python -m telegram_mcp.telegram_bot setup
```

Введите токен скрытым вводом в терминале. Единственный найденный личный чат
выбирается автоматически; при нескольких чатах выберите свой из списка.
Получатель фиксируется локально, ИИ не задаёт адрес доставки.
Используйте бота без настроенного webhook.

Проверка отправки:

```bash
.venv/bin/python -m telegram_mcp.telegram_bot test
```

Команда отправляет тестовое сообщение в настроенный чат. Повторная отправка
того же теста пропускается, если его доставка уже подтверждена.

## Запуск

В первом терминале запустите сборщик:

```bash
.venv/bin/python -m telegram_mcp.telegram_collector run
```

Во втором терминале запустите MCP с туннелем ngrok:

```bash
python3 scripts/start_mcp.py
```

Скрипт подготовит `.venv`, установит зависимости и запросит authtoken со страницы
[ngrok](https://dashboard.ngrok.com/get-started/your-authtoken).
Токен вводится скрыто и не сохраняется в файлы. Его также можно задать
переменной окружения `NGROK_AUTHTOKEN`.

Сервер слушает `127.0.0.1:8765`. Скрипт выводит **Server URL**
вида `https://…/mcp/<секрет>`. Адрес с секретом используется для инструментов
и событий; его нужно скопировать целиком. Оба процесса должны работать;
остановка — **Ctrl+C**.
Остановка скрипта MCP закрывает туннель и завершает сервер.
MCP также принимает команды Telegram-бота; отдельный процесс бота не нужен.

Для автоматического перезапуска MCP при редактировании кода и инструкций:

```bash
python3 scripts/start_mcp.py --reload
```

Uvicorn отслеживает Python-файлы в `telegram_mcp/` и Markdown-файлы в
`prompts/`. После сохранения файла перезапускается MCP, туннель ngrok
продолжает работать с тем же URL. Во время перезапуска запрос может прерваться.
Изменения должны попасть на компьютер, где запущен сервер. Сборщик запускается
отдельно; после изменения его кода перезапустите его вручную.

## Подключение ChatGPT

1. Откройте **Plugins → «+» → Add custom MCP server**.
2. Укажите название `My PC Test`, URL из терминала и **Authentication: No authentication**.
3. Создайте и установите подключение, затем выберите его через `@`.
4. Для проверки попросите вызвать `hello_from_my_pc`.

Секретная часть URL хранится в `.local/telegram/events-key` и сохраняется
после перезапуска. В интерфейсе ChatGPT выбирается No authentication:
доступ к подпискам защищён самим секретным адресом. Не публикуйте полный URL.
Обычный `/mcp` также обслуживает инструменты без авторизации, включая чтение
выбранных чатов и отправку сводки, но не позволяет управлять подписками Events.

Пример задания:

> Получи новые сообщения доступных чатов, составь выжимку по инструкциям
> сервера и отправь её через send_telegram_summary в мой личный чат с ботом.
> Разрешаю передачу этой сводки настроенному получателю.

Это задание можно использовать для расписания в ChatGPT. Если в задании
перечислены конкретные чаты, обрабатываются только они.

## Запрос выжимки из Telegram

Настройте бота и запустите MCP. В ChatGPT подключите полный Server URL
с секретной частью, затем обновите сведения подключения. Событие
`summary.requested` должно появиться на странице плагина рядом с инструментами.
Если URL подключения нельзя изменить, создайте подключение с новым адресом.

В Work-чате ChatGPT выберите плагин и один раз задайте:

> Подпишись на событие summary.requested этого MCP. Когда оно поступит,
> вызови get_analysis_instructions, получи новые сообщения выбранных чатов,
> составь выжимку по инструкциям и отправь через send_telegram_summary
> в настроенный личный чат с ботом. Разрешаю передачу сводки этому получателю.

Проверьте, что ChatGPT действительно создал задание с подпиской.
Поддержка MCP Events зависит от доступности Work и событийных заданий
в аккаунте и рабочем пространстве. Если события не отображаются или ChatGPT
не может создать подписку, команда бота сама по себе не запустит анализ.
Механизм описан в [документации MCP Events](https://developers.openai.com/plugins/build/mcp-events).

После настройки отправляйте боту `/summary`. Бот принимает команду только
в личном чате настроенного получателя и только от его аккаунта. `/help`
показывает подсказку. Команда не выбирает чаты: используются доступные источники
и правила задания ChatGPT. Анализ выполняется асинхронно.
Если новых сообщений нет, текущий промпт не предусматривает отправку сводки.

Если подписки нет или она истекла, бот сообщает об этом. Поддерживается одно
активное задание на настроенного получателя; перед созданием другого отключите
прежнюю подписку в ChatGPT. Подписка выдаётся максимум на сутки, её продление
ChatGPT выполняет через `events/subscribe`. Отмена задания вызывает
`events/unsubscribe` и останавливает последующие уведомления.

Подписки, ключи подписи, очередь событий и позиция чтения команд хранятся
в `.local/telegram/events.sqlite3`. После перезапуска очередь продолжается;
повтор одного Telegram update не создаёт ещё один запрос. Неудачная доставка
события повторяется с задержкой до пяти попыток с тем же event ID.
Ответ `2xx` подтверждает получение события ChatGPT, а не доставку готовой сводки.
При окончательной ошибке доставки бот сообщает о сбое. Команды старше пяти
минут не запускаются при разборе накопившихся Telegram updates.
Подписанные callback-запросы отправляются только на проверенные публичные
HTTPS-адреса без переходов по перенаправлениям.

MCP должен быть единственным получателем updates этого бота. Перед повторным
`telegram_bot setup` остановите MCP. Одновременный запуск копий на компьютере
и VPS не поддерживается.

## Инструкции для анализа

Редактируйте `prompts/mcp_instructions.md`, чтобы задать темы, критерии полезности
и формат отчёта. Перед анализом ИИ вызывает `get_analysis_instructions`:
инструмент читает файл при каждом вызове и возвращает полный текст.
Для изменения этого файла не нужны перезапуск MCP и обновление подключения.
После изменения инструментов обновите подключение в ChatGPT.
MCP перезапускается автоматически с `--reload`; при обычном запуске
перезапустите его вручную.

Промпт задаёт краткую выжимку, пропуск рекламы и повторов, ссылки на источники
и отправку готового отчёта в Telegram. Для каждого чата выполняется один запрос
за запуск. При отсутствии новых сообщений отправка в Telegram не выполняется.
Содержимое переписки рассматривается как данные для анализа.

## Сбор и выдача сообщений

Сборщик опрашивает Telegram раз в минуту. Начальная дата сбора — за сутки
до первого `setup`; она сохраняется в конфигурации и применяется также
к добавляемым источникам. Затем каждый чат собирается с последнего сохранённого
ID. После простоя сборщик догружает пропущенные сообщения. Запись сообщения
и отметки сбора выполняется одной транзакцией, без дублей при перезапуске.

Сохраняются текст, подписи к вложениям, время отправки, ID автора и ссылки
на сообщения каналов и супергрупп. Приватные ссылки доступны участникам источника.
Файлы, фото и голосовые не скачиваются; правки и удаления не синхронизируются.
База хранит собранную переписку без автоматической очистки.

При запросе MCP выбирает все ещё не переданные сообщения за последние 24 часа.
Период отсчитывается от времени запроса на компьютере и сравнивается со временем
отправки сообщения. Расчёт выполняется в UTC. Количество сообщений не ограничено.
Сообщения старше суток хранятся в базе, но не передаются ИИ, в том числе после
длительного простоя.

Отметка последнего переданного ID хранится отдельно для каждого чата
и сохраняется после перезапуска. Она общая для всех подключений и разговоров
ChatGPT, использующих этот сервер. Сообщения считаются переданными при вызове
инструмента, до анализа ИИ. При сбое ответа или анализа они не возвращаются
автоматически.

Длинная сводка отправляется частями как обычный текст; HTML и Markdown
не интерпретируются. Подтверждённые части записываются в журнал отправок.
Повтор идентичного текста тому же получателю через того же бота пропускает
подтверждённые части. При сетевом сбое после фактической отправки, но до ответа
Telegram API, возможен повтор части.

## Инструменты MCP

| Инструмент | Назначение |
| --- | --- |
| `hello_from_my_pc()` | Проверка подключения: приветствие, проверочный код и время UTC. |
| `get_analysis_instructions()` | Полный актуальный текст правил анализа и доставки сводки. |
| `list_telegram_chats()` | Выбранные чаты, количество сохранённых сообщений и время последнего сообщения. |
| `get_telegram_messages(chat_id)` | Ещё не переданные сообщения чата за последние 24 часа. |
| `send_telegram_summary(text)` | Отправка готового отчёта настроенному получателю. |

.venv/bin/python -m telegram_mcp.telegram_collector run --once

## Перенос на VPS и обновления

На VPS нужен Linux с systemd, Python 3.10+, `venv`, `pip`, `rsync`
и SSH. Пользователь SSH должен иметь право выполнять `sudo` (либо быть root).
На Ubuntu/Debian установите зависимости на VPS:

```bash
sudo apt update
sudo apt install python3-venv python3-pip rsync
```

Остановите локальные MCP и сборщик перед первым переносом. Это фиксирует
состояние баз и исключает одновременную работу двух копий Telegram-сессии.
На своём компьютере из корня проекта выполните, подставив SSH-адрес VPS:

```bash
python3 scripts/deploy_vps.py init ubuntu@YOUR_VPS
```

Первый перенос выполняется через `scp` в `~/MCP_hh` пользователя SSH
(`/root/MCP_hh` при подключении под root).
Каталог должен отсутствовать: команда откажется перезаписывать имеющуюся
установку. Копируются код, промпт, тесты и рабочие файлы `.local/telegram/`.
Для SQLite создаются согласованные копии через backup API. Локальные `.venv`,
Git, настройки IDE и резервные каталоги не копируются.

На VPS создаётся новое окружение Python. Введите ngrok authtoken в скрытом
вводе; он сохраняется на VPS в `.local/ngrok.env` с правами `600`.
При необходимости `sudo` запросит пароль пользователя VPS.
Сервисы `telegram-mcp` и `telegram-collector` запускаются сразу, при загрузке
VPS и восстанавливаются при завершении процесса. Не запускайте локальные
копии параллельно с VPS.

Посмотрите URL в журнале VPS и проверьте адрес подключения в ChatGPT:

```bash
ssh ubuntu@YOUR_VPS
sudo journalctl -u telegram-mcp -n 50 --no-pager
```

После изменения кода выполняйте на своём компьютере:

```bash
python3 scripts/deploy_vps.py update ubuntu@YOUR_VPS
```

Обновление останавливает сервисы, передаёт изменения через `rsync`,
устанавливает зависимости и запускает сервисы снова. `.local/`, `.venv/`,
Git и остальные файлы вне списка кода не синхронизируются и не удаляются.
Удалённые локально файлы внутри каталогов кода удаляются и на VPS.
Если обновление прервалось, исправьте ошибку и повторите `update`:
автоматического отката нет, сервисы могут остаться остановленными.

Для нестандартного порта добавьте `--port 2222` к `init` или `update`.
Можно указать имя VPS из `~/.ssh/config` вместо `user@host`.
Для нового инструмента после выкладки нужен Refresh details в ChatGPT.

Просмотр журналов и ручное управление на VPS:

```bash
sudo journalctl -u telegram-collector -f
sudo journalctl -u telegram-mcp -f
sudo systemctl restart telegram-mcp telegram-collector
sudo systemctl stop telegram-mcp telegram-collector
```

## Структура и локальные данные

```text
telegram_mcp/
  mcp_server.py       # инструменты и запуск MCP-приложения
  telegram_collector.py # сбор сообщений Telegram
  telegram_storage.py # чтение базы и отметки выдачи
  telegram_bot.py     # команды setup и test для бота
  paths.py            # пути к данным и промпту
  bot/
    commands.py       # приём /summary и обработка Telegram updates
    delivery.py       # Bot API, настройка и доставка сводок
  events/
    http.py           # HTTP-запросы MCP Events и проверка адреса с секретом
    subscriptions.py  # список событий, создание и отмена подписок
    queue.py          # очередь /summary, отправка и повторные попытки
    webhooks.py       # проверка callback-адресов, HTTPS и подписи
    storage.py        # SQLite, настройки владельца и секрет адреса
scripts/              # запуск MCP, перенос и обновление VPS
prompts/              # инструкции для ИИ
tests/                # тесты
.local/telegram/      # локальные настройки, сессия и базы
```

В `.local/telegram/` хранятся:

| Файл | Содержимое |
| --- | --- |
| `config.json` | Ключи приложения Telegram, выбранные чаты и начальная дата сбора. |
| `account.session` | Сессия личного аккаунта Telegram. |
| `messages.sqlite3` | Сообщения и отметки сбора. |
| `delivery.sqlite3` | Отметки передачи сообщений ИИ. |
| `bot.json` | Токен бота и получатель сводки. |
| `bot-outbox.sqlite3` | Подтверждённые отправки частей сводки. |
| `events-key` | Секретная часть адреса MCP Events. |
| `events.sqlite3` | Подписки ChatGPT, очередь событий и позиция чтения команд бота. |

Каталог `.local/` исключён из Git. Сессия и ключи дают доступ к аккаунту
и боту: вводите их локально и не публикуйте. MCP не возвращает их в результатах
инструментов.

## Тесты

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют хранение, восстановление сбора, отбор за последние сутки,
исключение повторов, отправку ботом, регистрацию и доставку событий MCP.
Внешние обращения Telegram и callback в тестах
заменены заглушками, реальные сообщения не отправляются.
